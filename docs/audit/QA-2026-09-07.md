## 5. Fusion / risk infrastructure (sections 4–6 of the brief)
Already in place before this audit (Release 1–2, ops 5212–5215, shipped on main): JHSIGNAL-1.0 contract with strict
validation (zero / null / missing / stale distinct, non-finite rejected), engine registry with criticality, 17 adapters
across MACRO / RISK / FLOW / FUNDAMENTAL / MARKET / CATALYST, evidence-cluster independence + correlation discount,
contradiction kept separate from the score, coverage that falls (never rises) when inputs disappear, CRITICAL
dependency → `CAPITAL_DECISION_BLOCKED`, ledger, replay-safe pure core, read API v1, Fusion Desk, and the graded
shadow ledger (`jh_fusion` in justhodl-signals). Opportunity discovery (opportunities endpoint), thesis confirmation
(family/cluster scores), entry timing (TACTICAL horizon / velocity) and risk permission (capital_decision) are separate
fields; a hard veto zeroes the opportunity rank and nothing overrides it. Heuristic scores are labelled as such
(`methodology` block); no calibration is claimed.

Two authoritative risk decisions coexist today and this audit did not merge them: Perplexity's
`justhodl-khalid-risk` (homepage authority block, khalidrisk.html) and the brain `justhodl-risk-gate` (which the fusion
layer treats as CRITICAL). They agree at the moment (NEUTRAL / SELECTIVE, sizing 0.75, cap 50%). Unifying them is a
policy decision, not a code fix — flagged, not changed.

## 7. Remaining issues and exact blockers
- B4 payload size (khalid.json 12.9 MB per view) and B5 DEGRADED evidence quality: inside the Khalid engine boundary (2026-09-04 directive). Recommended: publish a compact `data/khalid-summary.json` read model and move the ledger to a `?full=1`-style route; source the governed fusion from L1 root evidence (the JHSIGNAL bridge already produces 17 root-evidence adapters it could subscribe to).
- 87 missing engine inputs: needs a per-engine triage (some readers are dormant by design — see fleet-health doctrine); not touched here because each is its own engine.
- Fleet-wide output contract (section 3): JHSIGNAL-1.0 covers the fusion path; a fleet-wide envelope for all 882 engines is a migration, not a patch — `config/engine-contracts.json` (learned) is the current compatibility layer.
- Monitoring (section 9): fusion exposes `JustHodl/Fusion` metrics and per-run reports; a fleet-wide "last success / last attempt / overdue" surface exists partially (`/system.html`, feed-registry) and was not extended in this pass.
- Nothing in this pass touched AWS resources, S3 data, or production pages.
