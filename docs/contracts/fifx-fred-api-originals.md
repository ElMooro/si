# FI/FX complete FRED API originals

Six original CSV requests timed out in the retained September 29 run. All six official definitions were present in the bound canonical snapshot. Its 4,000-row observations responses were partial requested populations and cannot substitute for full-history FI/FX calculations.

The native engine now requests the official FRED observations API for those same six identities, once each. The observation window remains 1988-01-01 through the original request's UTC day; the realtime window is explicitly that day. Requests use native units, ascending observations, output type 1, offset zero and a 50,000-row limit. The eleven quote requests, four concurrent workers, admission deadline, resource settings and original weekday 21:20 UTC schedule are unchanged. No additional MOVE request is added.

Existing FRED environment keys or the existing SSM parameter are resolved only during ordinary acquisition. SSM uses bounded connect/read timeouts and one attempt; a successful cached credential expires after thirty minutes. The public request identity excludes the key. Redirects are refused, and a key echoed in retained response headers or body prevents public retention. Credential and transport failures retain only an error class. No keys are printed, added to source, or requested from the owner.

Whole original JSON bytes and their acquisition receipt are retained without conversion to synthetic CSV. The decoder requires exact typed request controls and count equal to the complete returned population, rejects partial pages, duplicate keys/dates, aggregation, changed vintage, nonfinite numbers and future observations, and preserves every numeric lexeme and missing value. A request crossing midnight retains its original request vintage. Each source declares its provider, original public request, requested observation/vintage window and returned/reported row counts. Complete requested window does not mean full series history or a point-in-time backtest.

The separate independent verifier parses original API JSON without importing the candidate decoder and checks all calculations at higher precision. Six 550-row invented API histories reproduce their CSV arithmetic exactly. Whole native retention tests keep all eighteen sources and all compiler bytes; the new decoder cannot be omitted or substituted. Historical CSV archives accept only explicitly reviewed predecessor hashes in their original compiler slots. Archived code is never executed: current reviewed code must reconstruct each original output and proof exactly.

Qualification of request parsing and arithmetic is separate from delivery. Exact package/receipt/runtime acceptance and old archive replay cannot establish recovery of a new ordinary publication. The read-only operation reads only the exact release receipt, control-plane configuration and approved public immutable originals. It does not invoke the engine, accelerate its schedule, probe a provider, read current/private/account/consumer packets or write native data. New API delivery remains unverified until the normal publication's complete originals are accepted. Forecast, Calls and portfolio sizing authority remain disabled.

The source-details panel distinguishes the requested observation window, response realtime window and returned/reported counts. It never promotes complete requested coverage to full-series or first-release history. Error/missing responses cannot display complete coverage. Both original CSV and quote sources retain their existing metadata without invented API windows. At narrow phone widths, definition labels and values stack for readability. Whole invented browser evidence includes all eighteen sources, 3,804 original rows and 3,410 historical calculations.
