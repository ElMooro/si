# FI/FX complete transport and exact predecessor replay

An invented 55-byte CSV response reproduced a truncation bug in both native readers: one `read(limit+1)` returned a legal seven-byte fragment and both readers accepted it. The HTTP receipt also recorded seven bytes despite a 55-byte Content-Length.

The shared local transport routine now reads bounded binary fragments to EOF, refuses oversized/nonbinary fragments, closes on every success or failure and checks declared lengths without treating booleans as integers. Every native S3 read requires the SDK's positive ContentLength and verifies all stored bytes. Compressed canonical FRED evidence is checked at both the stored-container and bounded decoded-body layers; immutable reference checks still establish the decoded identity.

HTTP acquisition keeps the existing public source plan, one attempt per source, four concurrent workers, serial durable callbacks and original 100-second admission budget. It requests identity encoding, requires the original URL, rejects partial/ranged or unexpectedly encoded responses and validates a single decimal Content-Length when provided. Complete HTTP error bodies remain retained with their original non-200 status. No provider fallback, retry, paid API, resource change or schedule change is introduced. Provider availability is not repaired merely by correcting transport.

All mathematical compilers and qualifications remain byte-identical. Historical replay accepts only the two exact preserved transport predecessors in their respective compiler slots: fifx_store `46421fb3b919245412532b1410366524eda9ba6b1cb46214dff6de6183afe6f7` and fifx_acquire `810bba6d56ce5d32c7072034d7bcc828f63000c681fdb8cc5148f2b191e566ec`. Archived source code is never executed. Altered predecessor bytes or a correct hash placed in another module's slot are rejected.

The whole preceding source files and test runner are retained as inert fixtures. Ten new native transport cases join the existing 22 cases. They cover fragmented bodies, exact bounds, malformed lengths, closure, gzip, HTTP errors, partial responses, original URL identity, whole 18-source replay, predecessor safety, failed retention acknowledgements and exact historical compatibility. Two operation tests require type-sensitive native runtime identity and receipt-only access.

Read-only operation 6379 verifies the exact new native receipt/package and original settings before and after replaying the complete retained public archive. It never reads current/private/account/consumer packets, invokes a producer, contacts providers or changes AWS data or schedules. A new native publication awaits its original weekday 21:20 UTC schedule.
