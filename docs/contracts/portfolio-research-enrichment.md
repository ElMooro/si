# Complete, identified portfolio research enrichment

The portfolio snapshot joins four existing research documents to its positions and watchlist: alpha scores, confluence, regime picks and sentiment. These remain descriptive model outputs. A retained response and a unique symbol join do not establish source freshness, independent evidence, predictive validity or permission to size a position. Existing automatic-watchlist rules, quote acquisition, holdings arithmetic, capital blocking and native schedules remain separate.

## Retained source and complete-record limits

The existing S3 reader now returns its original dictionary together with read evidence, without injecting metadata into that source dictionary. Each complete response is preserved as original base64 bytes, SHA-256 and byte count, with its requested key, acquisition start/end and a source-declared generated_at when present. The declared time is not validated as freshness or first availability. Complete invalid JSON is retained but supplies no research fields. Incomplete responses and byte-bound refusals never claim complete retained originals. Stream cleanup is attempted on every path; an unconfirmed close is recorded separately without exposing raw error text.

The handler retains at most 8 MiB of complete research response bytes across the four documents, with the same per-document ceiling. There is no row selection or partial-document acceptance to fit this budget. A document exceeding its per-read ceiling is explicitly unavailable. If the sum of complete retained bodies exceeds the total ceiling, the handler stops before automatic sync, mark collection and publication. Bounds are operational limits, not completeness certification for a provider universe. Original JSON decoding remains strict about duplicate keys, nonfinite values, Unicode, EOF and declared byte length.

`research.source_documents` retains the complete originals. The six join summaries refer to the four source documents; the three confluence groups are not claimed as independent evidence. A symbol's research_evidence gives the source key, array path and every zero-based occurrence needed to identify its source row. Missing/malformed arrays have unavailable counts, distinct from an explicit empty array. Invalid identifiers remain in original source evidence and have recorded occurrence indices. Repeated symbols, including identical duplicates, do not select a winning row. Symbols appearing in multiple confluence tiers have no preferred tier.

## Descriptive fields and missingness

Valid risk-flag and signal lists and sentiment explanations are preserved whole. There is no three-item or 140-character storage truncation. Malformed field types become null with an explicit invalid_fields entry; their original representations remain in the retained bytes. Measured zero, signed regime adjustments and empty lists remain distinct from absence. Alpha scores require typed finite values in 0..100, ranks positive integers and known tier labels. Confluence counts require nonnegative integers. These checks do not validate the economic meaning or calibration of the underlying models.

Research field values must also fit the existing browser snapshot identity contract. Unsafe numbers and excessively nested structures are withheld from displayed fields, with complete originals retained. This avoids an unsupported metadata value invalidating the identity check for the entire book. Valid complete component structures are preserved; numerical definition, source age and independence remain unverified. The watchlist sorts valid scores, including zero, ahead of unavailable scores, with a deterministic symbol tie-breaker. A string-valued score can no longer crash publication.

Before either snapshot sink is written, the complete document must fit the existing private mirror's 20,000,000-byte limit using its actual spaced JSON encoding. Oversized snapshots fail before either sink writes; they are not shortened. This guards one publication's size and does not make the Worker and S3 writes atomic, protect concurrent writer order, bound the total quote-fetch workload or establish actual private publication success.

## Acceptance

The original 52,028-byte handler and seven complete invented predecessor failures remain inert. Twenty-eight focused tests run current code with invented source documents, books and publishers. They check full evidence retention, duplicate/ambiguous identities, field types, complete source clocks, cleanup, failure recovery, ordering of known/unknown scores, browser-representable values and both source/publication bounds. Eleven complete current scenarios retain their inputs, original byte-bearing requests, outputs and mocked writes. Source comparison restricts this repair to research loading, indexing, enrichment and the handler.

The snapshot candidate ZIP must pass all 123 unit cases and four handler integrations through the offline validation path. Related admin, risk and scenario checks and full frontend/deployment suites remain required. Native acceptance is read-only: exact receipt, complete source closure, live alias and original resources/schedules. Static acceptance compares whole served assets with the intended build. No actual private account, current consumer packet, provider request, native producer invocation or real portfolio write is used for acceptance. Capital sizing stays blocked. UI presentation of this additional research evidence remains a separate acceptance step.
