# Security and Fusion audit remediation — 2026-09-09

This implementation closes the verified INST-01/INST-05 residuals and Fusion D1–D4 in source. Production closure additionally requires the containment and verification steps below. Tests use synthetic fixtures; no customer note bodies, journal records, billing changes or provider credentials were retrieved by the local test suite.

## Private research boundary

The full engine originals remain at their existing S3 keys for same-account IAM consumers. Cache-Control alone is not authorization. Install both statements generated by `aws/ops/checks/audit_20260909_security.py`, preserving unrelated bucket policy statements. Their `StringNotEquals aws:PrincipalAccount` condition denies anonymous and unrelated AWS accounts, including signed external accounts.

Eight authenticated Worker mirrors are available through `GET/HEAD /private-artifact?kind=<kind>` or the old `/data/<kind>.json` aliases: brain, brain-history, journal-graded, my-brief, devils-advocate, notes-index, notes-themes, playbook-rules. Verified owner and trusted service identities can read; only the service can publish with PUT. Responses are private/no-store and bypass all caches. Unauthenticated requests return 401; unrelated accounts return 403. Missing publication returns 503, never a public fallback. The raw `data/tradingview-notes.json` corpus remains IAM-only and has no browser mirror.

`data/_askdesk/*`, `data/search/index/*`, and `equity-research-history/*` are IAM-only archives. Historical versions of the sanitized deterministic feeds and root `equity-research/*.json` are IAM-only; the exact canonical key and prefix lists are exported by the checker. Root legacy aliases are also denied. The deterministic current feeds retain safe numeric fields, signal IDs and provenance; copied personal text is removed. Full notes and analyses remain in the protected originals. The notes/brief/rules public siblings contain public-safe projections.

Brain and Journal UI clear personal state immediately on auth changes and discard late responses from a prior account. Brain pending saves are bound to their originating UID; obtaining a replacement session cannot send the previous account's drafts. Imports/OCR check the account again after parsing. Authenticated fallback reads never request a raw public original.

The personal Ask HTTP route requires verified owner/service identity; the Worker supplies the service token to the Lambda, whose direct HTTP interface independently checks it. Public Ask Desk accepts only catalogued public source keys and explicitly rejects private artifacts and archives before any IAM read. Ask Desk itself needs no service token.

## Durable journals and billing

The existing SQLite `WORKSPACE_COORDINATOR` Durable Object binding serves isolated `journal:<uid>` and `billing:<uid>` names. No new class, migration tag or Supabase DDL is required. Existing home-workspace operations are unchanged.

Journals migrate lazily from existing KV, retain the original KV source and a durable legacy baseline, then use explicit revisions. Locked decisions cannot be edited or removed; corrections append and retain their target. Competing writes return 409 with the current revision. Each revision has an immutable event record. Documents are chunked into bounded durable values; a synthetic journal larger than 2 MB is tested. New timestamps, actor identity and revision are server generated. Entry prices are explicitly marked `client_reported`; this is a research decision log, not verified brokerage executions.

Billing customer ownership is established from Stripe customer metadata or unambiguous legacy subscription UID history before binding it durably. Profile IDs are migration hints, not proof. Checkout and the billing portal use the same verified binding. New customer creation has a stable per-user Stripe idempotency key. Every new webhook reconciles the current customer-wide subscription list, including pagination and replacement subscriptions. Historical webhook status/price/plan is never a fallback. Unknown active prices or unavailable Stripe state fail closed and remain retryable.

A serialized Durable Object queue, durable event markers, outbox and monotonically versioned projection prevent concurrent delivery races. The projection commits before advisory external writes. Supabase `profiles.plan` and KV `plan:<uid>` remain advisory mirrors and never grant authorization. An external write left in flight across a crash therefore cannot elevate access. Webhooks retry until the advisory mirror succeeds.

`GET /plan/self` requires a verified user; `GET /plan/service?uid=<uid>` requires the service token. Both read only the durable Stripe projection, whose validity deadline is five minutes. Expiry refreshes current Stripe state or returns 503. Browser entitlements only accept this authority and enforce its deadline even if timers are suspended. Editable user metadata and profile/KV plan values are ignored. The AI proxy forwards these routes and their authentication rather than synthesizing tiers. Repository searches found no other active plan-reading implementation; `settings.html` reads `JustHodlAuth.getTier()`.

## Fusion

Companion commit `4ca378a` validates the real producer contract, coherent snapshot/run timestamps, nested rows, finite metrics, per-signal TTL and critical readiness. Execution eligibility and shadow research eligibility are distinct. All read projections apply the same readiness decision. `fusion.html` consumes one validated full API snapshot and expires it at the supplied deadline; it no longer bypasses the API through raw state feeds. Research inspection is explicit. A mock fixture generated by the actual Python producers is tested.

## Production prerequisites and order

1. Deploy the data Worker, AI proxy, updated auth/pages and all companion producer changes together with the new shared modules. Keep the existing SQLite Durable Object binding/migration. Worker secrets already required: ADMIN_TOKEN, STRIPE_SECRET, STRIPE_WEBHOOK_SECRET, SUPABASE_SERVICE_KEY; vars SUPABASE_URL, PRICE_PLAN_MAP and owner binding must remain correct. No SQL management credential is needed.
2. Install both bucket deny statements before opening any regenerated public derivatives. Preserve all original/current objects and historical versions. If the shared execution role is used, grant only the exact service-token SSM parameter; do not grant it to public Ask Desk.
3. Provide JH_SERVICE_TOKEN or authorized `/justhodl/api-admin/token` access to brain-sync, journal-grader, my-brief, devils-advocate, notes-intel, playbook-engine and ask. Seed the eight private mirrors directly from their existing IAM originals, without printing payloads. Maintain `owner:uids` for the journal grader's default owner selection.
4. Run the reviewed containment migration: sanitize existing deterministic current objects, regenerate public siblings, rebuild the TradingView provider shard and provider index, and reset the symdir warm cache. New producer source alone does not rewrite old cached objects.
5. Purge the affected site/Worker URLs and HTML/auth assets, including root aliases. The Worker also changes its Cache API epoch and adds an upstream cache generation for sanitized feeds. Previously downloaded browser copies cannot be recalled; the new UI stops unauthenticated retrieval and discards prior-account responses.
6. Run the read-only checker with IAM S3 and optionally the service token. It reads policy and HEAD metadata only: anonymous source access denied, same-account source retained, authenticated mirrors ready with no-store. Require recorded production evidence for all these checks; a local test pass is not production verification.

Do not roll back to the old Worker/profile entitlement reader or public mirrors after migration. Keep the S3 deny statements and durable account records during any rollback. Journal legacy KV is preserved for recovery, but it is no longer the writable authority. If a historical Stripe customer lacks independent ownership evidence, repair that binding through verified operator evidence; do not reinstate profile-tier fallback.

Provider credential rotation remains a separate external action coordinated by the release owner; removing literals does not invalidate previously published credentials.
