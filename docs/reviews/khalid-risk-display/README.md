# Khalid risk explanation coverage — draft

PR34's naturally published [risk packet](https://justhodl.ai/data/khalid-risk.json) at 2026-10-01 08:20:54 UTC contained four withheld-authority diagnostics. The [Khalid packet](https://justhodl.ai/data/khalid.json) at 08:25:50 referenced that exact publication and copied its closed policy correctly, but omitted every diagnostic. Its renderer therefore had no explanation field to display. PR34 backend acceptance is complete; visible explanation acceptance is open until this separate slice is deployed and naturally published.

## Change boundary

- `aws/lambdas/justhodl-khalid/source/risk_diagnostics.py` projects the already-read, already-accepted risk artifact into one additive `risk_authority_diagnostics` field. Four fixed source identities, exact known diagnostic versions/code/effect/contracts/paths/canonical explanations, literal critical boolean, numeric finite nonnegative source ages and timezone-bearing bounded clocks are required. The input collection is capped at 64; output is always four rows. Duplicate source rows, source mismatches, unknown versions or malformed fields produce unavailable rows, never neutral numbers. Arbitrary producer text, additional fields or private locations are not copied.
- The single additive handler expression cannot change policy, actions, board, sizing, thresholds or existing clocks. Exact risk generation/expiry and the original source clocks are retained in the presentation field. Existing feed reads/writes remain unchanged; no new endpoint, collection, provider or schedule.
- `khalid.js` inserts the explanation panel directly below the existing risk summary. In DATA_HOLD it names that state; each known row names its INVALID status **at publication**, canonical explanation, exact source timestamp and source age at publication. It explicitly labels the material as dated explanatory evidence, not current permission. It does not claim that a historical explanation is fresh now. Rows stack at mobile width. Unknown/old packets show four explicit unavailable explanations. DOM writes use textContent, and the renderer checks the same known contract identity and matches the publication reference before showing an explanation.
- No HTML, CSS, chart files, risk producer, risk policy, Katlin, configuration or workflows change. Existing Pages content-hash stamping versions the changed controller.
