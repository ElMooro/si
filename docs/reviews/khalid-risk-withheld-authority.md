## Bounded implementation and validation

`withheld_authority_diagnostic` recognizes exact known contracts, literal false call/sizing flags and null authority fields. For the bond desk it requires the explicit UNQUALIFIED block, null score and literal false permissions. Null alone, unknown versions, malformed scores, truthy strings and zero-valued permission flags do not establish explicit abstention. This is a description of the producer's declaration, not validation of that producer's methodology. Missing/transport failures keep their original explanation. No producer free text or replay locations are copied.

The diagnostic is additive after the existing acceptance decision. It cannot enter the active feed set or relax policy. Fifteen native risk tests include 42 whole-output paired cases against the complete retained pre-change engine; stripping only `authority_diagnostic` makes outputs identical. The fixture is SHA256 pinned (`c13582bae17050bd5ad94074b3522d08f81507bdd157f6169e6b416fd1cef099`). An AST comparison proves all pre-existing policy code is unchanged. Tests cover isolated/combined withdrawals, missing/empty/transport failures, stale/future clocks, all postures, score boundaries, malformed scores, input immutability, and conservative diagnosis matching. Invented fixtures are labeled as such; they are not market observations.

Run: `python aws/lambdas/justhodl-khalid-risk/tests/run_tests.py`. Full gates passed: 2,357 frontend tests, 70 Khalid native tests, 15 risk tests, 1,018 deployment regressions plus 15 shell checks, 599 page graphs, wiring (36 pages / 143 engines), preflight and diff checks. Deployment tests used dummy credentials with external sockets blocked; emitted deployment/invocation receipts were fixtures. Release requires independent exact-head review; no merge, invocation, provider call or schedule change is authorized by this draft.

The separate [Katlin consumer trace and pending proposal](katlin-unqualified-shortage-trace.md) has no production effect. The existing Khalid consumer is also executed offline against the new output: the closed policy passes its contract, while entry/cap/sizing mutations remain rejected.
