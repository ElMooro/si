# News Flow public-history consumer repair

The alert-history read now uses `/data/alert-history.json`. It requires `public_alert_schema=alert-history-public.v1` on successful JSON responses. The consumer never reads HTTP error bodies or retries through an alias. HTTP 503 is explicitly unavailable or withheld with its cause unverified; 404, transport, parsing and invalid-contract states remain distinct. Only a received, validated empty public projection yields zero published alerts. Counts describe loaded events rather than today's events or active alert authority; aggregate incomplete counts are qualified.

All source strings are escaped before HTML rendering; only locally authored numeric pills use HTML. Severity classes use a fixed vocabulary. Malformed companion rows cannot erase the other seven sections. Null/blank/boolean measurements do not become zero, and real numeric zeros survive. The original navigation, eight filters, companion URLs, section limits, shared script includes and five-minute interval remain. Overlapping loads are coalesced; completed reloads replace prior state, including failure and recovery.

Page retrieval is explicitly separate from source `generated_at` publication and `as_of` observation. Missing clocks remain unavailable; alert `sent_at` is labeled Sent. Event publication/report/observation labels identify their source field, with no fabricated current time or freshness threshold. The legacy writer's `last_run` is not treated as publication or observation proof.
