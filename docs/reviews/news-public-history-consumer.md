# News Flow public-history consumer repair

The alert-history read now uses `/data/alert-history.json`. It requires `public_alert_schema=alert-history-public.v1` on successful JSON responses. The consumer never reads HTTP error bodies or retries through an alias. HTTP 503 is explicitly unavailable or withheld with its cause unverified; 404, transport, parsing and invalid-contract states remain distinct. Only a received, validated empty public projection yields zero published alerts. Counts describe loaded events rather than today's events or active alert authority; aggregate incomplete counts are qualified.

All source strings are escaped before HTML rendering; only locally authored numeric pills use HTML. Severity classes use a fixed vocabulary. Malformed companion rows cannot erase the other seven sections. Null/blank/boolean measurements do not become zero, and real numeric zeros survive. The original navigation, eight filters, companion URLs, section limits, shared script includes and five-minute interval remain. Overlapping loads are coalesced; completed reloads replace prior state, including failure and recovery.

Page retrieval is explicitly separate from source `generated_at` publication and `as_of` observation. Missing clocks remain unavailable; alert `sent_at` is labeled Sent. Event publication/report/observation labels identify their source field, with no fabricated current time or freshness threshold. The legacy writer's `last_run` is not treated as publication or observation proof.

Validation before review: 2,660 frontend/worker tests passed, including ten new whole-inline-consumer synthetic tests. All 599 page graphs parsed; wiring check (36 pages/143 wires), secrets check and 15 public-boundary tests passed. Offline Chromium at 1440×1000 and 390×1000 exercised all eight sections, literal hostile strings, keyboard filtering/pressed state, 503 unavailability and empty recovery without overflow or script errors. The browser and VM each recorded eight consumer requests per completed load before/after (only alert history changes origin); overlapping load adds none. The seven companion endpoints are unchanged. Shared scripts/fonts are intercepted in this isolated browser test, so this does not claim full live-page browser acceptance.

Reproduce: `node --test tests/news-public-history.test.js`; `node tests/news-public-history.browser.cjs` (Playwright with `/usr/bin/chromium`). Fixtures and intercepted responses are synthetic only. No live bucket requests, provider calls, Lambda invocations, test notifications, writer/storage/ACL/guard changes or public marker writes were performed. No incremental recurring provider requests: the guarded history read replaces the existing history read. GitHub Pages/CI and ordinary static/guarded verification requests may incur their usual service cost; no measured billing amount is available.

Release and exact-head review evidence will be appended after the draft review and deployment gates. The public history producer/projection remains outside scope; an unavailable live history cannot be repaired by making private diagnostics public.
