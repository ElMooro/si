# JustHodl AI live rollout automation

Status: **implemented, not executed**

`aws/ops/pending/justhodl_ai_live_rollout.py` is the approved production
orchestrator for the AI cornerstone rollout. It is fail-closed, resumable, and
uses only AWS APIs through `boto3`. It does not deploy the Cloudflare Worker.

## Safety contract

- The default is `--plan`. A push-triggered `run-ops.yml` execution therefore
  performs live identity/inventory reads and writes a plan report, but makes no
  AWS changes.
- `--apply` also requires the exact phrase:
  `I APPROVE JUSTHODL AI PRODUCTION ROLLOUT`.
- STS account `857687956942` and session region `us-east-1` are checked before
  any mutation.
- All three EventBridge rules and all three SQS event-source mappings are
  disabled at the start and after every failure.
- The base and consumer stacks are deployed only through deterministic named
  CloudFormation change sets. The script emits their resource-level summaries
  before execution and waits for terminal success.
- Consumer and main-function packages use SHA-256-addressed S3 keys. Existing
  objects are reused only when their checksum metadata matches.
- The consumer template is statically checked to contain exactly three
  mappings with `Enabled: false`; the base template must contain exactly three
  rules with `State: DISABLED`.
- Canonical `data/brain.json` is copied from `justhodl-dashboard-live` to the
  private stack bucket with SHA-256 metadata, an AWS checksum, SSE-KMS, and an
  observed destination version. The exact version is read back and hashed
  before the dashboard deny policy can be merged.
- The dashboard policy merge replaces only the two reviewed statement Sids and
  proves all unrelated live statements are byte-equivalent after the update.
- The current Lambda zip, role, full environment, published version, and aliases
  are captured before cutover. Secret-bearing rollback state is stored in
  Secrets Manager; the repository report contains only environment key names
  and content digests.
- The new Lambda package includes `requirements-governance.txt`. Code is updated
  first; role and environment are updated separately. Environment variables are
  merged, not replaced, and existing secret values are never printed.
- `AI_CANARY_APPROVAL_TOKEN` is created/read in Secrets Manager by default (or
  an operator-selected SSM `SecureString`) and injected into the Lambda without
  entering logs or reports.
- The controlled SageMaker canary requires an existing `InService` blue
  endpoint, a manually `Approved` model package, an owned green endpoint
  configuration, bounded inference probes, and a complete rollback plan. It
  deploys, invokes, grades, performs and verifies a live rollback drill, then
  repeats the controlled canary for the final promotion.
- EventBridge/SQS activation occurs only after the canary passes, the shared DLQ
  and all three consumer error alarms are `OK`, each alarm is wired to
  `jh-ops-alerts`, and the Lambda code/config rollback evidence is independently
  re-read.
- A post-canary failure restores the SageMaker blue configuration, restores the
  Lambda code/role/environment/aliases, and leaves all consumers disabled.

## Required reviewed canary input

Apply mode requires a reviewed JSON file. The workflow default path is
`aws/ops/pending/justhodl_ai_canary_input.json`; it is intentionally not
generated by the rollout because probes and model selection require human
review.

```json
{
  "endpoint_name": "jh-ai-existing-blue",
  "green_endpoint_name": "jh-ai-approved-green-canary",
  "green_endpoint_config": "jh-ai-approved-green-config",
  "model_package_arn": "arn:aws:sagemaker:us-east-1:857687956942:model-package/justhodl-ai-prod/1",
  "green_estimated_hourly_cost_usd": 0.42,
  "estimated_cost_usd": 1.0,
  "health_probe": {
    "content_type": "application/json",
    "body": "{\"inputs\":[\"reviewed health input\"]}"
  },
  "canary_requests": [
    {
      "content_type": "application/json",
      "body": "{\"inputs\":[\"reviewed grading sample\"]}"
    }
  ],
  "rollback_plan": {
    "blue_endpoint_config": "jh-ai-existing-blue-config",
    "blue_variant": "AllTraffic",
    "captured_at": "2026-09-10T00:00:00Z",
    "evidence_digest": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
  }
}
```

The endpoint, model package, and green configuration must carry the reviewed
`justhodl-ai-owner=JustHodl` tag required by the application canary. Missing
input, missing resources, non-approved models, ownership mismatch, failed
inference/grading, or failed rollback is a hard failure.

## GitHub Actions operation

A dedicated workflow is **not required**. The existing
`.github/workflows/run-ops.yml` has narrow, rollout-only manual inputs and
passes the required CLI arguments only when the selected script is
`aws/ops/pending/justhodl_ai_live_rollout.py`.

### Plan

Use workflow dispatch with:

- `script`: `aws/ops/pending/justhodl_ai_live_rollout.py`
- `apply`: `false`

The same plan is run automatically if the pending script reaches `main`. A
successful plan is deliberately retained in `pending/`; it is not auto-moved
to `ran/`.

### Apply

Use workflow dispatch with:

- `script`: `aws/ops/pending/justhodl_ai_live_rollout.py`
- `apply`: `true`
- `approval_phrase`: `I APPROVE JUSTHODL AI PRODUCTION ROLLOUT`
- `canary_input`: path to the reviewed JSON file

The standard workflow AWS access-key secrets and region setting are used. The
script rejects any configured region other than `us-east-1`. No approval token
is passed through GitHub Actions.

## Reports and resume behavior

The machine-readable report and non-secret checkpoint are:

- `aws/ops/reports/latest/justhodl_ai_live_rollout.json`
- `aws/ops/reports/latest/justhodl_ai_live_rollout_state.json`

The run ID is deterministic over the reviewed templates and main source. A
rerun reuses checksum-addressed artifacts, executed/no-op change sets, verified
Brain versions, and the encrypted original rollback capture. A saved promoted
canary is accepted only if the live endpoint is still `InService` on the
reviewed green configuration; otherwise the controlled canary is rerun.

The report always contains a
`JustHodlAiExternalDeploymentNextStep/v1` entry for
`cloudflare/workers/justhodl-ai-proxy`. Cloudflare deployment remains a
separate reviewed action using the Cloudflare workflow and credentials.

## Local validation (no AWS deployment)

```bash
python -m py_compile \
  aws/ops/pending/justhodl_ai_live_rollout.py \
  aws/ops/tests/test_justhodl_ai_live_rollout.py
python -m unittest -v aws/ops/tests/test_justhodl_ai_live_rollout.py
```

Do not run the rollout script itself during repository validation: even its
default plan contacts AWS for target verification and live observations.
